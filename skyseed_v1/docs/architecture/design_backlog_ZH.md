# 设计待办

本文保存已讨论、但尚未实现或接纳为当前架构的设计方向，使灵感能够跨对话和交接保留，又不会被误认为现有产品行为。

这里的条目不是实现承诺、发布阻断、昂贵运行门禁或大范围重构授权。开始工作前必须根据当时的代码和测量重新检查假设。

## 维护方法

- 讨论形成具体方向、取舍或未决问题且工作有意暂缓时增加条目；
- 记录价值、必须保留的内容和未决点，不能只记文件名或机制；
- 状态使用 `explore`、`candidate`、`ready`、`implemented`、`retired`；
- 进入 `ready` 需要明确决策、有界范围和相称验证，而不是反复口头同意；
- 实现后链接架构决策、指南、测试或发布证据，并保留可追溯动机；
- 列在这里不会自动成为门禁；门禁必须保护当前不变量或合理失败面，并进入相应测试/运维策略。

## D-001 — 把 `frozen` 变成显式编译边界

**状态：** candidate

当前 frozen 流程的核心价值是分离逻辑描述/规划和具体执行。运行时应消费有 schema 版本、不可变的计划，而不是在 epoch 边界静默重算路由或后端动作。无界网络最终需要滚动编译：当前 horizon 运行时编译 successor 并 inactive 准备，边界只负责激活。

必须保留确定性时间/后端计划、输入身份/schema/hash/资源引用覆盖、inactive 准备与边界激活、禁止静默重规划/回退，以及执行、可视化、审计共享的产物。未来应区分物理链路采样、地面资格、编译更新计划、主机绑定缓存和历史重放，不把它们全叫 frozen；将面向产品的词汇细化为 `compile_run_plan`、`seal_build_manifest`、`load_compiled_plan`、`activate_prepared_generation` 等真实契约；便携语义计划与主机路径、PID、接口、诊断和清理观测分离；把历史自证迁入聚焦测试/审计；分别测量规划、编译、序列化、hash、externalize 和验证。

这是 v1 封版后的架构细化，不授权删除当前成功准备路线。

## D-002 — 把 Skyseed 发展为可组合仿真平台

**状态：** explore

Skyseed 面向研究者构建自己的卫星互联网、实验平台和算法，而不只运行 S4/S5。未来要决定公开 `SkyseedEmulator` 组合对象；可按需安装的星座、连通、路由、动态、互联网接入、观测和应用/service layer；用户模型和 planner 扩展接口；在版本化 adapter 后映射 SEED 对象/编译器；哪些 IR 是公开兼容契约；以及如何选择 Docker/Linux/BPF 或未来后端而不污染逻辑描述。

示例应继续是易懂的公开 API 组合根和演示，不能实现平台内部。

## D-003 — 泛化地面预设与时长资格

**状态：** candidate

S4/S5 地面预设只对声明开始时间和窗口提供有界证据；两小时 S5 分析不是地球相对周期证明。未来可提供声明 shell、epoch、时长、步长、可见性与存活/覆盖标准的构建器；把来源和资格边界嵌入预设；定义减少 GW/UT 又保留地理和连通性的策略；用统一方法重新验证 S4/S5；明确改变日期、延长有限运行和最终无限运行的行为；必要时发展滚动资格或在线地面策略。

不能仅为允许更长命令削弱当前时长门禁，必须显式替换不变量。

## D-004 — 以模块契约构建长期测试策略

**状态：** candidate

局部变化通常由廉价稳定测试验收。测试跟随行为契约和模块边界迁移或重写，而非重构后整批复制。目标包括纯模型/planner/compiler/小状态机单元测试；IR、后端计划、身份、归属、失败语义契约测试；组合、SEED 编译、worker 交接和有界后端集成测试；只在无法更廉价覆盖有序消费时使用 replay；真实主机、规模、资源尾部和长期问题才使用 system/长跑。历史实验是证据和潜在夹具来源，不自动成为永久门禁。

## D-005 — 完成外部可视化集成

**状态：** explore

v1 已有交换位置和导出器。集成前需版本化轨道/卫星身份和同步时间戳、UT/GW/zone 身份、物理链路采样和计划/运行切片、实验/run 身份和示例 output 下的产物发现、live/offline 消费和可接受观测延迟，以及两个项目独立演进时的兼容行为。可视化只能消费权威计划或观测，不能成为第二个拓扑 planner 或运行时反压源。

## D-006 — 把可观测性成本作为可测工程成本

**状态：** candidate

控制台、持久证据、计时和审计有价值，也有非零成本。要求不是绝对零开销，而是成本可见、可归因、适当有界且不悄悄成为更新大头。未来分别归因规划、编译、后端应用、观测、序列化、审计；发现重复全局扫描、大对象重复序列化、锁争用和跨计时边界工作；按卫星、地面节点、候选链路、epoch 规模比较；测量证明很小的同步机制可以保留；时间异常只触发调查，不在仍有进度时自动杀进程或改写功能结果。

Shell ID 不是规模排序：S1=1584、S2=1584、S3=720、S4=348、S5=172。成本要使用卫星、轨道面、跨轨候选 slot、地面资源、运行 slot、epoch 和后端物化组成的复杂度向量。S5 不能证明 S3 能安全启动；S3 真实运行前需要离线拓扑/容量/成本预览和合格地面预设。

## D-009 — 提供阶段感知的操作者进度

**状态：** candidate（第一阶段已实现）

持久快照已有阶段年龄、子进程、容器数/样例、资源和 epoch 计数。优先做小型阶段投影：低频心跳复用快照，不新增 Docker 扫描；无可靠分母时显示阶段年龄和活动操作；Compose build 说明只构建镜像，up/readiness 展示 created/running/ready/required 和容器样例；只有生产者给出权威总数时才显示进度比例；清理显示已有的剩余资源数；未来可有只读 `status`。

不能为分母未知的工作伪造百分比。当前已实现全部不变阶段的有界心跳、真实 Compose batch、活动命令摘要、容器状态、默认简短 preflight、范围清理和自动移除退役 SEED `PYTHONPATH`。后续仍可增加更全面总数、`status` 和可选 build log 产物。
