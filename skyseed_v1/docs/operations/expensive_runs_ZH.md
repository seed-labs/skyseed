# 昂贵运行策略

本手册把稳定化经验中长期有效的部分适配到重构后的 Skyseed v1 架构，刻意短于旧的逐事故门禁表面。

## 永久不变量

以下规则保护网络正确性，继续采用失败关闭：

- 每个标准示例只有一条可见执行路线；
- 严格 `bpf_owned` 转发不存在隐藏 Linux/core 回退；
- 未来状态先以 inactive 方式准备，只在边界变为可见；
- worker、预加载、写入或清理的部分成功绝不记录为 ready；
- 审计只报告证据，不能修复出 PASS；
- 清理后仍保留首次失败证据；
- 归属资源有明确所有权和零残留验证；
- 控制台、观测和产物展示不能反压网络激活。

## 真实运行前的廉价门禁

只使用与合理后期失败对应的检查：

1. 示例直接 `inspect`；
2. 运维 `preflight`；
3. profile `preview` 和目录/容量契约；
4. 聚焦单元/契约/集成测试；
5. runtime、worker、backend、loader 或验收行为改变时运行更广的廉价回归；
6. 只有 prepared 生命周期语义改变时才做有界生产者/消费者重放。

通过所有历史脚本不是门禁。检查只有仍保护当前不变量或合理失败面时才留在这里。

## 证据，而非自动阻断

- 总阶段时间及与最近成功运行的比较；
- 未启用严格 deadline 时的 activation lag；
- 超过实际所需容量的磁盘压力；
- 仍有进度时的启动时长，以及独立零残留生命周期门禁成功时的清理时长；
- 报告大小和观测新鲜度。

这些指标触发调查，但不会杀死仍在前进的运行，也不会静默改变路线。时间本身不改写功能成功；只有语义契约失败才会使运行失败。

## 已退役事故保护

当前表面有意不包含：S4 命名的隐式默认值、示例间 profile 继承、旧 `satellite/configs` 下的 fallback profile 查找、旧 runner 别名和 capped/short 兼容 profile、绑定单一历史产物位置的审计 reader，以及能由准备时或 pending-record 聚焦检查替代却仍在 live epoch 全局扫描的规则。

历史可以描述这些机制，但当前代码、CLI、profile 和主要文档不能把它们提供为可执行替代路线。

## 修订规则

保护规则阻碍有效进展时，先找出它原本保护的不变量，再用最廉价且范围正确的契约测试或准备检查替换，随后删除过时规则。禁止新增 flag、fallback、兼容分支或第二 profile 路线绕过。

用户长跑前只需记录：准确示例/命令/输出目录、刚通过的廉价门禁、prepared horizon 覆盖、禁止工作、预期计时参考，以及仍可能导致后期失败的显式风险。
