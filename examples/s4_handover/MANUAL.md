# Manual network experiment

[中文](MANUAL.zh-CN.md) · [Build and run](README.md)

Complete [development setup and the build](README.md) first. With the local shortcut configured:

```bash
skyseed
cd examples/s4_handover
python run.py
```

The map and its etcd service start and stop with the run. The first run builds the image. Rebuild with `python map.py` after changes to the map code.
Open [InternetMap2](http://localhost:8080/pro/map). The network repeats the
600-second scenario until Ctrl+C in the running terminal.

## Work from the map

- Click a node to inspect its container, identity IP, interfaces and peers.
  Satellites also show orbital grouping, sampled position and current serving Zones.
- Double-click a node or choose **Launch console** to enter its container.
- Click a link to inspect both interfaces and link parameters, and open either endpoint.
- UT is on the left, satellites form orbital-plane rings, and GS are grouped on the right.
  Regions follow Scene size; nodes cannot be dragged.
  The status panel shows cycle time and the current UT serving satellite.

Ordinary links appear when an endpoint is selected. Check **Show all links** to
see the whole network. UT access remains visible. Captured traffic reveals its
links anywhere on the map and keeps them highlighted for 2.5 seconds after the last packet.

## Watch Zones and send from satellites or GS

Select a GS, then use **Choose Zone** in its details to select an associated Zone.
A satellite offers the Zones it currently serves. Selected Zones appear in a fixed
watch area below the orbital rings. They remain when selecting other nodes, opening
terminals or refreshing the page. Choose **Unwatch** in a Zone's details to remove it.
Opening or refreshing the page also includes the current UT's Zone, even with an old
saved watch list. It can still be unwatched during that visit.

Click a Zone to see its **Zone IP**, current serving satellites and associated GS.
Purple dashed lines represent service relationships. At handover, the Zone stays
in place and its service line moves to the new satellite. **Launch console** opens
the corresponding satellite or GS. From an associated GS, send to the Zone:

```bash
ping ZONE_IP
```

From the current serving satellite, send to an associated GS:

```bash
ping -I ZONE_IP GS_IP
```

Zone details provide commands with the addresses filled in. Choose **Copy** and
paste into the corresponding terminal. After handover, use the Zone details to open
the new satellite; existing terminals stay in their original containers.

A serving satellite can also use `nc -s ZONE_IP GS_IP 9090` to connect to a listening
GS. In the reverse direction, run `nc -l -p 9090` on the serving satellite and
`nc ZONE_IP 9090` on an associated GS. Zone addresses act as application endpoints.
Handover moves the address and delivery location, while nc and its TCP state stay
on the original satellite. Use UT↔GS below to observe a persistent TCP connection across handovers.

## Send from UT

The UT details list three associated GS and their addresses. Start with **Akita** to
observe inter-satellite forwarding. Replace `GS_IP` with its address and run in UT:

```bash
ping GS_IP
```

For TCP, run in the selected GS:

```bash
nc -l -p 9090
```

Then run in UT:

```bash
nc GS_IP 9090
```

Type a line and press Enter at either end; observe reception at the other end.
Keep these windows open and enter satellites from the map to observe their connections.

## Observe handover and traffic

In a node terminal, inspect interfaces or capture packets:

```bash
ip -br addr
tcpdump -i any -nn
```

`tcpdump` shows packets on the current container’s interfaces, including labels
in MPLS packets. Ctrl+C stops the capture.
In the map's **Filter**, enter `not ip6` and Submit. Nodes and links flash with traffic;
expand **Log** for full node names and packet text. This includes IPv4, ARP and MPLS,
while excluding IPv6 background traffic generated by Linux interfaces. `all` includes
that background traffic. `icmp`/`tcp` match ordinary IP segments; use `ether proto 0x8847`
for MPLS transit segments. The current `any` capture environment does not support the
`mpls` filter keyword. Clear Filter and Submit to stop capture.

To retain manual traffic observations, click **Record** in Log, perform ping/nc,
then **Stop recording → Save** to download JSONL. It includes packet text, labels,
containers and interfaces/peers from the latest state, for comparing observations
across nodes by time. Save before refreshing, clearing Log or starting a new recording.
The run's `execution.jsonl` continues to record network changes; packet records are saved by the browser.

At handover the UT link moves to its new satellite. Enter the old and new satellites
and run `ip -br addr`: `ssut` disappears on the old satellite and appears on the new one.
UT keeps `192.0.2.2`. Click the current access link to compare both interfaces and addresses.

To observe the regional outage, switch the destination to **Yamaguchi** and start a
new ping or nc session. The outage occurs at 180–240 seconds each cycle: affected
GS–satellite interfaces and their map links disappear, then return when service resumes.
Continue typing in the UT/GS nc windows
to observe delivery before and after the interruption.

## Host shortcuts

For host-side queries, open a terminal:

```bash
skyseed
skytime
skynodes
docksh NAME
```

`skynodes` lists the UT, three GS and serving satellite container names.
`dockps` lists running containers. Use `exit` to return from a container.

## Stop

Press Ctrl+C once in the running terminal and wait for UT, map and network cleanup.
`output/runs/<run>/` retains execution receipts, UT attachment records, map inputs and diagnostic logs.

After an abnormal exit, confirm that the original run has ended, then use the repository root:

```bash
docker compose -f examples/s4_handover/output/seed/deployment/docker-compose.runtime.yml -p skyseed-s4 down
docker ps -a --filter label=skyseed.example=s4-handover
docker ps -a --filter label=skyseed.runner
docker ps -a --filter label=skyseed.internet-map
```

Identify remaining containers from this run and clean them up with
`docker stop NAME` and `docker rm NAME`.
