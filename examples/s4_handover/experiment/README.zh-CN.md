# S4：区域断链与持续连接

[English](README.md) · [主流程](../README.zh-CN.md)

本例使用 348 颗 S4 卫星、32 个按地域固定选取的地面站和 732 个全球分区。
先构建场景、部署文件和预计算计划，再循环执行这份 600 秒计划，直至 Ctrl+C：第 180–240 秒中断指定区域的
星地连接，观测同一条 UT–GS TCP 连接在服务卫星切换和链路恢复后的表现。


## 手动循环

[手册](../MANUAL.zh-CN.md)给出 nc、抓包、换星时刻与接口观察方法。`repetition.py` 将
保存的 BPF 计划时间向前平移，每轮边界只补终点到起点的差异；容器、节点地址、UT 和
应用进程保留。它是本例的人工回跳，不是连续轨道传播，也不重新计算 P&C。
`console.py` 提供终端状态与 Ctrl+C 到 `Runner.stop()` 的绑定。`run.py` 显式选择是否循环。

默认、备用只表达距离顺序。三条方向配对均计算，但不会按可达性改变关联，也不会把
既有 TCP 会话迁移到另一 GS IP。手动测试备用 GS 时，需要应用明确连接那个地址。

## 使用流程

使用唯一的[主流程](../README.zh-CN.md)。本目录只放这些入口调用的 UT、干扰、
Store 托管和观测辅助。计划全部在 Run 前计算，View 独立读取保存产物。

## 覆盖、Zone 与业务路径

GS 接入依次经过地球无遮挡、仰角 ≥5°、连接选择与 5 秒建链准备。
S4 为 560 km、97.6° 倾角的六轨道面单壳；全球分区不表示地表连续覆盖。



| 关系 | 默认规则 | 不代表什么 |
|---|---|---|
| Zone → 关联 GS | 按分区中心至 GS 的球面距离，本例静态取最近 3 个（模型默认仍为 1）；等距按节点 ID | 不保证该 GS 当前有星地连接或端到端路径；不按可达性改选 |
| Zone → 服务卫星 | 每次评估选中心点仰角最高且 ≥5° 的卫星，无候选则无服务 | 不保证分区每一点都覆盖，也没有计算用户终端无线链路预算 |
| 实验 UT → 接入卫星 | 跟随实际采用的该 Zone 末端规则建立临时 veth | 不属于 Perturbation 管理的 GS 链路，也未叠加独立 UT 无线时延或丢包 |

UT 按自身位置选择分区；该 Zone 中心为 (33.75°N, 117°E)，服务星仍由分区中心选取。自动业务使用默认 GS Yamaguchi。图上的绿色亮线是该业务
当前规则推导的路径，包含星间及最后的星地段；紫线是 UT 临时接入；灰蓝线是其他活动
连接。Zone 选择框与边界点击可查看其他分区的关联 GS、末端规则和几何参考；这不会
改变实际流量的两端。仰角/斜距采用模型位置插值，实际接入仍以执行记录为准。

## 一份包怎样传输

UT 应用使用稳定地址 `192.0.2.2`，关联 GS 应用使用 Compiler 分配的稳定节点地址（用 `skynodes` 查询）。没有 IP-in-IP、地址转换或第二层 IP 头。

```text
UT: 192.0.2.2 → 默认 GS，原始 TCP/2323 包
  → 接入 veth → 服务星入口按目的分类并压标签
  → 星间只按本地 label 查表、换标 → 默认 GS 弹标 → GS 应用

GS 回包: 默认 GS → 192.0.2.2
  → GS 入口把 UT /32 映射到其 Zone 的标签路径
  → 星间换标签 → 当前服务星弹标签
  → 临时 IP 路由 192.0.2.2/32 via 接入 veth → 同一个 UT
```

`ut/routing.py:TerminalRoutingModel` 继承默认 GZ 算法，在三个关联 GS 分别增加上述入口规则，
复用 Zone 路径的下一跳和标签；不新增 UT 的全网路由、不改变中间节点的标签规则。
这条规则随正常计划生成、保存、编译和发布，连接不可达时也不会自行选择别的 GS。

换星只重建接入 veth、调整末端交付；UT 容器、应用地址和同一 TCP socket 保留。
TCP 只 connect/accept 一次，按序号发送并核对原样回显，
不自动重连。这里运行的是普通 TCP echo，没有 Telnet 的协议协商或远程登录。

入口/出口处理原始 IP 包，中间卫星按本地入标签查表，换成下一接收节点的标签并 redirect。
标签写入、swap、表查询和出口选择由 BPF 完成；标签头的 push/pop 使用 Linux TC
MPLS action。没有路由协议守护进程，也没有 Linux MPLS 路由表。接口断开时，出口
绑定缺失导致丢包。配置与数据包格式见 [UT 说明](ut/README.zh-CN.md)。

## 怎样解释恢复现象

| 观察 | 解释与证据 |
|---|---|
| TCP 仍长时间没有回复，随后原连接继续 | 丢失的段在超时后重传，连续超时会加大等待；网络恢复不会主动重置发送端计时器 |
| 换星前后序号连续、只有一次 connect/accept | 支持该次实验同一 TCP 会话持续；不等于过程中无丢包或无暂停 |
| 测量结束仍有未回复探测 | 保留 pending 记录，不计为成功；异常关闭/提前超时仍报告错误 |

TCP 超时退避依据 [RFC 6298 §5](https://www.rfc-editor.org/rfc/rfc6298.html#section-5)。
要区分网络恢复和应用恢复：对照 veth 恢复回执，再查看 `ut.pcap` /
`gs.pcap` 中同一 TCP 序号的重传时间。结果页保留实际回复、最长暂停和错误，不把暂停
归为 Runner 的执行延迟。端点抓包只能证明端点收发，不能充当卫星逐跳抓包。

每次运行的实际恢复时间和完整输入保存在对应 run；端点 PCAP 仅在 `run.py` 设置
`CAPTURE = True` 时保存，手动模式默认不抓包。先看结果页中的测量，再用执行回执和
已有 PCAP 核对原因。换星或断链恢复的成功不表示每次运行的等待时间都相同。

## 区域断链 Model

[perturbation.py](perturbation.py) 定义 `RegionalGroundOutage`。时段、圆形区域和
跨批次状态由 Model 自己持有；`simu.py` 注册它：

```python
link.set_perturbation_hook(RegionalGroundOutage)
```

改为 `link.set_perturbation_hook(None)` 可关闭本例干扰。基础 LinkPlan 保持原样，
Network 仍依据基础计划计算路由。扰动只修改执行分支，因此不会通过预先绕路隐藏断链。
ISL 和 UT 接入不受该模型影响。窗口结束时恢复当时基础计划仍存在的连接和最新属性。

日本圆覆盖 Yamaguchi；西欧圆中的站点以 `build.json` 导出的清单为准。范围由球面距离与固定半径决定，
不是按地图投影画圆，也不是电磁传播模型。圆形是便于阅读的示例假设；真实干扰可由
天线方向、频段、地形和接收门限改变边界。没有计算 SINR，也没有模拟圈内 UT 的无线失效。

| 合同 | 用途 |
|---|---|
| `perturb(plan)`、`self.layer.scene` | 处理输入计划，读取框架关联的场景 |
| `plan.initial_links`、`plan.operations` | 读取边界状态和有序变化 |
| `LinkOperation.apply(links)` | 在本地工作状态应用建立、撤销、更新 |
| `LinkPlan(start, end, initial, operations)` | 返回保留区间和接续关系的执行计划 |
| `state_at(t)`、`states_at(times)`、`slice(start,end)` | 查询或切片已生成计划 |

`outage_description()` 仅给本例页面导出区域、时段和 GS 清单，不是通用扰动可视化接口。
运行输入会冻结本次配置，后续修改 Model 不会改变已有结果的解释。

## Store、工具与回放

Scene、Physical、Link、Network 和 Compiler 页面调用既有 `tools/observation/` 工具。
[执行记录工具](../../../tools/observation/execution/README.zh-CN.md)负责将计划与实际回执关联。
本目录 `observation/` 保留固定流量统计、UT/圆形干扰叠加和总览编排；这些是特定示例的
展示源码，生成结果仍写入 `output/views/` 或 `output/runs/<run>/views/`。

| 数据 | 用途与生命周期 |
|---|---|
| 通过 `Store` 访问的 etcd 数据 | 跨进程共享键值、事务、revision 与订阅；Runner 实时写事件，测量结束后批量归档 |
| etcd 数据库与 WAL | 服务管理的持久化数据，停止后保留 |
| `store.json` | 运行结束后的便携导出副本 |
| 执行／测量 JSONL | 可追加的离线历史；UT 跟随进程读取执行 JSONL |
| PCAP | 端点抓包 |
| `inputs/` | 本次运行冻结的 Scene、编译计划、设置及绘图观察 |

`Store` 将值编码为 JSON 字节，通过 etcd API 读写；大体量计划和抓包仍保留为文件。
Run 在本机随机端口启动 etcd 3.6.5，归档后停止；执行记录使用 `runner/events/`，
业务测量使用 `user/`。本例尚未通过 etcd 协调 P&C 调度或多机时钟，离线回放不需要
etcd 服务。源码分工与输出布局见[主说明](../README.zh-CN.md)。

3D 页面用冻结指令与实际生效回执恢复链路、标签和 UT 接入。橙色区域和 180–240 秒
窗口是干扰配置；GS 连接数、路径和恢复时刻按实际回执展示。流量统计另行显示真实
TCP 回复和断链窗口。位置来自计算时保存并随本次运行冻结的观察资料，回放不调用模型；路径动画表示已采用规则的推导结果，
不是逐跳抓包。回执也不等于每项内核状态的独立读回。
