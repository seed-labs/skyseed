# Skyseed Next

本仓库用于重新设计和实现卫星互联网仿真系统。

本项目不是对旧版本代码的整体重构或迁移，而是在重新完成系统设计的基础上，以可验证的小步迭代方式建立新的实现。

旧版本中已经验证过的算法、运行机制和性能优化不会被直接丢弃，但也不会被整体复制到新系统中。只有当当前设计涉及相关能力时，才对旧版本进行定向调查，并在新设计的边界内重新吸收其中有价值的经验。

---

## 1. 协作分工

### 设计

系统目标、领域概念、对象职责、模块边界、接口合同、状态模型和测试要求，由用户与 GPT 讨论并确认。

设计结论应逐步写入仓库中的正式文档，不能只保留在聊天记录中。

### 实现

Codex 根据已经确认的设计负责：

* 编写和修改代码；
* 编写并运行测试；
* 更新与当前实现直接相关的文档；
* 执行必要的真实运行验证；
* 报告结果、问题和证据。

Codex 不应在实现过程中自行改变整体架构或扩大对象职责。

当现有设计无法合理实现时，应先报告冲突和可选方案，再由用户与 GPT 决定是否修改设计。

---

## 2. 循环开发流程

项目按模块或垂直切片持续循环推进。

### 1. 设计当前切片

先明确当前要解决的问题，并完成必要的设计，包括：

* 目标和范围；
* 对象或模块职责；
* 输入与输出；
* 关键合同和约束；
* 测试与验收方式。

在设计尚未明确前，不直接进入大规模实现。

### 2. 判断是否需要参考旧版本

检查当前能力是否与旧版本中已经实现或优化过的内容有关。

如果旧版本没有重要参考价值，则直接按照新设计继续。

如果旧版本可能包含有价值的算法、内核操作经验、性能机制或失败经验，则进入定向调查。

### 3. 定向调查旧版本

Codex 只调查与当前设计问题直接相关的旧版本内容。

调查的目标是理解：

* 旧版本实际实现了什么能力；
* 其中哪些机制经过了真实验证；
* 有哪些性能经验和失败经验；
* 哪些内容只是旧结构产生的偶然复杂性。

调查默认只读，不进行迁移或重构。

不得因为调查旧版本而：

* 按旧文件或旧类组织新系统；
* 整体复制旧控制流；
* 扩大到与当前切片无关的部分；
* 让旧版本结构反向决定新设计。

### 4. 修订并确认设计

用户与 GPT 根据调查结果判断：

* 哪些机制值得在新系统中重新实现；
* 哪些经验应转化为约束或测试；
* 哪些旧实现不应保留；
* 当前设计是否需要调整。

旧版本调查结果只是设计参考，不会自动成为新系统的设计。

### 5. 实现、测试和文档更新

Codex 按照确认后的新设计完成当前切片，包括：

* 代码实现；
* 单元测试和必要的集成测试；
* 必要的真实运行验证；
* 相关文档更新；
* 测试与运行证据。

实现应服从新系统的设计边界，而不是追求以最短方式复现旧版本行为。

### 6. 审查和修正

Codex 提交实现报告后，由用户与 GPT 检查：

* 实现是否符合设计；
* 测试是否验证了真正的合同；
* 是否引入了未批准的依赖或特殊路径；
* 是否出现旧版本结构渗透；
* 文档、代码和测试是否一致；
* 当前证据能够支持哪些结论。

发现问题后，继续修正，直到当前切片达到可接受状态，再进入下一轮设计。

---

## 3. 旧版本的定位

旧版本是：

* 工程经验来源；
* 已验证机制的参考；
* 性能基线；
* 历史失败案例来源；
* 必要时的行为对照。

旧版本不是：

* 新系统的基础架构；
* 等待整体迁移的代码库；
* 新系统运行时的 fallback；
* 新系统模块和对象划分的模板；
* 新实现成功的替代证明。

新系统不得依赖旧版本才能完成正式运行。

---

## 4. 基本约束

### 新设计优先

任何旧版本机制都必须适应新设计，而不是要求新设计迁就旧代码。

### 调查与实现分开

旧版本调查应先形成结论，再决定是否以及如何实现。不得在调查过程中顺便搬迁代码。

### 小步闭环

每一轮应完成一个可理解、可测试、可审查的切片，避免一次性实现过大的系统范围。

### 代码、测试和文档同步

实现完成时，相关测试和文档也应处于一致状态。

测试通过不能替代真实运行验证，真实运行成功也不能替代合同和单元测试。

### 不允许隐式绕行

不得为了临时跑通而加入未经设计批准的 fallback、兼容路径、特殊条件或第二条成功路径。

### 设计变更必须显式

实现过程中发现设计问题时，应明确提出设计变更，而不是通过代码细节悄悄改变系统行为。

---

## 5. 正式事实来源

仓库中的版本化内容是项目的正式事实来源，包括：

* 设计文档；
* 架构决策；
* 接口合同；
* 源代码；
* 测试；
* 可复现的运行证据；
* 当前开发状态。

GPT 和 Codex 的聊天记录与记忆仅用于协助工作，不能替代仓库中的正式记录。

---

## 6. 本文件的使用

本文件规定项目的基本设计与开发流程。

Codex 在开始新任务前应阅读并遵守本文件。

除非任务明确要求，否则 Codex 不应自行修改本文件。流程需要调整时，应先由用户与 GPT 讨论确认，再写入仓库。
