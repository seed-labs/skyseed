## Package-level findings

1. Every root-level module has a real architectural classification; none is an
   unclassified leftover.
2. Discoverability is nevertheless uneven. Concrete public class names are
   hidden behind abstract directories (`domain`, `contracts`) and generic
   filenames (`base.py`, `compiler.py`, `projection.py`).
3. The strongest one-file/many-concept cases are `domain/satellite.py` and
   `specifications.py`. `compose_project_launcher.py` and `scenario_loader.py`
   are large, but each still represents one cohesive boundary.
4. `domain` is not a framework-pure domain: `Satellite` and `GroundStation`
   intentionally are the same instances as upstream SEED `Node` and `Router`.
5. `contracts/identity.py → domain/validation.py` is the only current import
   from the Simulator-facing data boundary into the entity/domain directory.
