# Complete Static Emulator and Simulator Input

## 1. Status and scope

The complete handwritten static example is implemented. It combines two
isolated Satellites, one GroundStation, one ordinary seedemu AS/Network/Router,
one IX, explicit eBGP, immutable Simulator static input and Docker compilation.
It adds no GroundStation–Satellite link and no dynamic Simulator field.

## 2. Static input contract

`SimulatorStaticInput` contains only:

- `SatelliteSimulationInput` values;
- `GroundStationSimulationInput` values;
- a read-only pure-data index keyed by `NodeId`.

The input is frozen, sorted by complete logical identity and fails closed on
duplicates. It contains no Emulator entity, Registry, container, namespace,
Compose service, persistence object or execution target.

Construction is direct:

```python
simulator_input = create_simulator_static_input((skyseed_as,))
emulator_node_index = create_emulator_node_index((skyseed_as,))
assert {
    item.node_id for item in simulator_input.list_nodes()
} == set(emulator_node_index)
```

The aggregate generation function accepts only `SkyseedAutonomousSystem` values;
ordinary SEED AS objects fail closed rather than being silently ignored.
Adding entities after construction does not mutate the existing snapshot.
The separate Emulator node index is also read-only, but its values are the
exact original Satellite/GroundStation instances for later Compiler lookup.
It is never passed to the Simulator.

## 3. Per-entity conversion

```python
satellite_input = create_satellite_simulation_input(
    satellite,
    orbit.parameters,
)
station_input = create_ground_station_simulation_input(station)
```

`simulator_input_generation.py` owns this copying operation. The immutable input types contain
data validation and aggregation behavior only; there is no stateless
conversion class and no separately instantiated multi-AS builder.

## 4. Formal complete example

`examples/complete_static_emulator/main.py` directly shows:

1. `Emulator` and `SatelliteBase`;
2. `SkyseedAutonomousSystem`;
3. Shell → Orbit → two Satellites;
4. GroundStation construction and IX attachment;
5. ordinary AS → Network → Router and IX attachment;
6. explicit eBGP;
7. `create_simulator_static_input((skyseed_as,))`;
8. `create_emulator_node_index((skyseed_as,))` and equal-ID validation;
9. render and `SkyseedDockerCompiler`.

It deliberately imports no file-configuration operation. Its two cross-layer
outputs are generated by direct functions, with no facade or resolver class.

## 5. Identity and runtime separation

`NodeId` uses ASN, entity kind and stable entity ID. One private implementation
derives it for both static input and the Emulator node index. It is independent
of seedemu Registry types and Docker names and is not held by the entities.
Compiler metadata comes from the real entity and integration lifecycle, not
from static Simulator input.

Future plans will cite `NodeId`. A future Compiler update path will use the
index to recover the entity and then enter SEED compilation/resource handling.
Missing or duplicate IDs, wrong kinds and mismatched entity collections must
fail closed. No plan or update path is implemented in this slice.

## 6. Deferred work

Simulator runtime state, positions, visibility, dynamic links, resource
resolution and execution planning remain unstarted.
