# Complete Static Emulator and Simulator Input

## 1. Status and scope

The complete handwritten example is implemented. It combines two isolated
Satellites, one GroundStation, one ordinary seedemu AS/Network/Router, one IX,
explicit eBGP, immutable Simulator static input and Docker compilation. Its
Simulator entrypoint also loads the static Zone layout from `zones.yaml` and
exercises the implemented and accepted A–E Dynamic Slice main chain. The
Emulator/Compose side still adds no GroundStation–Satellite network
attachment.

## 2. Static input contract

`SimulatorStaticInput` contains only:

- `SatelliteSimulationInput` values;
- `GroundStationSimulationInput` values;
- a read-only pure-data index keyed by `NodeId`.

These types are owned by `skyseed_v2.simulator.static_input`. The
entity-aware copying functions remain outside that Simulator package in
`simulator_input_generation.py`.

The input is frozen, sorted by complete logical identity and fails closed on
duplicates. It contains no Emulator entity, Registry, container, namespace,
Compose service, persistence object or execution target.
All node queries accept only `NodeId`; no entity-ID string scan or fallback is
available.

External adaptation is direct after querying the real Base owner:

```python
base = emulator.getLayer("Base")
skyseed_autonomous_systems = base.get_skyseed_autonomous_systems()
simulator_input = create_simulator_static_input(skyseed_autonomous_systems)
```

The aggregate generation function accepts only `SkyseedAutonomousSystem` values;
ordinary SEED AS objects fail closed rather than being silently ignored.
Adding entities after construction does not mutate the existing input.
No NodeId-to-entity mapping is generated or passed to the Simulator.

## 3. Per-entity conversion

```python
satellite_input = create_satellite_simulation_input(
    satellite,
    orbit.parameters,
)
station_input = create_ground_station_simulation_input(station)
```

`simulator_input_generation.py` owns this copying operation. The immutable input types contain
data validation and aggregation behavior only; there is no stateless
conversion class and no separately instantiated multi-AS builder.

## 4. Formal complete example

`examples/complete_static_emulator/emu.py` directly constructs:

1. `Emulator` and `SatelliteBase`;
2. `SkyseedAutonomousSystem`;
3. Shell → Orbit → two Satellites;
4. GroundStation construction and IX attachment;
5. ordinary AS → Network → Router and IX attachment;
6. explicit eBGP;
7. the upstream `Emulator` returned as the helper's only value.

`main.py` imports this helper, creates one Simulator/Topology from that same
Emulator, preserves render and `SkyseedDockerCompiler` compilation, generates
output controls, then publishes the offline Topology and Zone tool snapshot.

`simu.py` imports the same helper but not `main.py`. As the external assembly
entrypoint it queries Skyseed AS values from `SatelliteBase`, invokes
`create_simulator_static_input(...)`, creates `SimulationTimeline` and
`SimulationDefinition(static_input=..., timeline=...)`, creates `Simulator`
and explicitly materializes `Topology` from the loaded
`ZoneLayoutDefinition`. It describes the result as the initial static
Simulator topology, not as a Slice. An unbounded Timeline is displayed through
a fixed prefix rather than fully consumed.

`emu.py` deliberately imports no file-configuration operation. Both canonical
entrypoints use only `load_zone_layout_definition(...)` for Zone input; the
cross-layer static node input is still generated by a direct function, with no
facade, index or resolver class.

`main.py` and `simu.py` support direct-file execution from their own example
directory. The private example runtime helper validates the caller's selected
interpreter and never switches environments.
The compilation entrypoint replaces its owned default output unless
`--no-override` is requested; module execution remains supported.

## 5. Simulator static materialization through Iteration 2

The materialized immutable tree is:

```text
Simulator
└── Topology
    ├── SkyseedAutonomousSystem[]
    │   ├── GroundStation[]
    │   └── Shell[]
    │       └── Orbit[]
    │           └── Satellite[]
    └── ZoneLayout [0..1]
        ├── Zone[]
        │   └── LatitudeLongitudeRectangle
        └── ZoneMembershipModel
```

Topology retains its AS tuple, ASN index, unified NodeId node index and optional
ZoneLayout.
Typed node queries use that unified index and check the object type. Shell and
Orbit facade queries delegate through the actual owners. No typed duplicate
node index, global Shell/Orbit index, Satellite-parent reverse API or reverse
index exists. Public tuple enumerations and each owner's private immutable
lookup return the same frozen object instances.

The Zone path is:

```text
zones.yaml / programmatic construction
→ ZoneLayoutDefinition
→ Simulator.create_topology(...)
→ Topology-owned ZoneLayout
→ Zone[]
→ fixed ZoneMembershipModel
→ Topology facade
```

The file-specific prefix is `raw YAML mapping/list →
LatitudeLongitudeRectangleDefinition → ZoneDefinition →
ZoneLayoutDefinition`. YAML is only an input source; its loader returns the
same definition type available to programmatic callers. The Definition is
consumed during atomic materialization and is not retained. `ZoneLayout`
solely owns the Zone tuple and ID index, and Topology's four Zone methods only
delegate to that same layout. A Topology without a layout remains valid.

The example uses manually chosen latitude/longitude query points. Those pairs
are arguments, not new domain entities. `find_zones(...)` prints every physical
membership; `resolve_zone(...)` prints the unique authoritative Zone chosen by
the active Model. It does not derive a query point from a Satellite or select a
Satellite for a Zone.

## 6. Identity and runtime separation

`NodeId` uses ASN, entity kind and stable entity ID. One private implementation
derives it for every static-input path. It is independent of seedemu Registry
types and Docker names, is not held by the entities and has no lookup ability.
`SkyseedDockerCompiler` metadata comes from the real entity and integration
lifecycle, not from static Simulator input.

Future plans will cite `NodeId`. Any later approved dynamic-execution update
path will use ASN to call Base `getAutonomousSystem()`, require a Skyseed AS and
dispatch the kind to existing `get_satellite()` or `get_ground_station()` owner
queries. Missing or duplicate IDs and wrong/mismatched kinds must fail closed.
No index, plan, resolution or update path is implemented in this slice.

## 7. Deferred work

Position, visibility, dynamic Connections, service-Satellite selection,
Slicer, Route and TopologySlice are implemented and accepted in A–E.
TopologyDifference, Planning, resource resolution and backend/runtime execution
remain deferred.
