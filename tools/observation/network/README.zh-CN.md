# GZ 路由检查示例

**中文** · [English](README.md)

使用[保存产物查看工具](../README.zh-CN.md)的 `write_network`，传入 Scene、
两份 RoutePlan、基础 LinkPlan 和绘图 context，打开生成的 `index.html`。
默认展示针对 GZ 模型，可作为自定义工具的起点。

| 操作 | 查看内容 |
|---|---|
| 选择 GS、Zone 和方向 | 固定逻辑通信对，播放时追踪服务星及完整骨干路径 |
| 规划范围／查看关联 GS 路径 | 说明当前通信对未关联的原因；点击后才切换 GS |
| Zone／服务／链路／两条路径图层 | 可以叠加显示；Focus 只聚焦当前路径和查看对象 |
| 点击节点、Zone 代表点或边界 | 查看对象详情，不改变通信对；节点显示当前分支的完整受管规则 |
| “用于路径查询” | 将所查看 GS 或 Zone 显式设为查询对象 |
| 路径节点按钮 | 直接查看该跳的完整规则表 |
| 更新事件按钮 | 跳转到准确生效时刻，包括 200 ms 的短暂窗口 |
| 计划详情 | 按当前查看的节点或 Zone、分支和时刻进入子页，筛选记录、展开完整字段或返回图形 |

边界、代表点和身份来自 Scene 的可选端点资料；没有边界就只画代表点。
服务虚线来自已记录的分配，不表示实际末跳链路。回程入口采用该时刻记录的服务星，
不推断终端迁移已执行。实际规则出口可能因 Delivery 延迟仍在另一颗卫星。
服务记录的求值时刻单独显示；未知、不可服务、缺少匹配、环路及不可用出口分别呈现。
未关联的 GS 不属于本次 GZ 计算覆盖的通信需求，不表示链路图上无路可走。
没有入口匹配规则时，若记录明确，就显示“未纳入规划”或“当前无服务卫星”；
仍然存在的实际转发路径继续显示，包括服务变化后尚未撤销的延迟规则。
没有关联记录时，规划范围保持未知。

`inspection_data(scene, base_plans, delivery_plans, link_plans, positions=..., evaluations=...)`
从计划读取规则，从保存资料读取几何和可选 GZ 观察，不调用模型。路径逐跳检查规则；
重叠 Delivery 上下文只计入一次，延迟尾部保持基础及链路最终状态并标记。
`write_network` 按基础计划分段展示，详情表保留原始批次，包括起点、新操作和上下文。
本工具展示计划，不代表实际报文或 Runner 执行。
